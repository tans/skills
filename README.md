# Skills

这里收录可直接交给 Codex / Agent 使用的技能。技能不是提示词合集：每个技能都定义了适用范围、执行约束、交付物和验证标准。把任务交给 Agent 时，明确点名技能即可让它按这些规则工作。

## 选用技能

| 任务 | 使用技能 | 适用场景 |
| --- | --- | --- |
| 做出能运行、演示和验收的业务产品 | `$jiege-hackathon` | 内部工具、管理后台、业务原型、小程序、爬虫、自动化，或把半成品补成可交付产品 |
| 生成或编辑项目图片 | `$jiege-imgen` | Logo、图标、Banner、封面、插图、背景图、空状态图，以及有参考图的改图、抠图、扩图 |

## 如何让 Agent 使用技能

在任务开头写出 `$技能名`，再说明目标、已有项目路径和你在乎的验收结果。Agent 会先读取对应目录的 `SKILL.md`，再按其中的边界和流程执行。

```text
使用 $jiege-hackathon，在 /path/to/project 中实现员工报修管理。
已有 Node 项目，请沿用现有技术栈。验收时我要能创建报修、查看处理状态，并在重启后保留数据。
```

### 产品与业务交付：`$jiege-hackathon`

它适合“把想法做成东西”的任务。新项目默认采用 Node.js + Koa + SQLite + DaisyUI；已有项目则优先沿用现有栈。它会围绕一条真实核心流程完成前后端、数据持久化、异常反馈、启动说明和实际验证，而不是只交付页面、截图或方案。

适合这样提需求：

```text
使用 $jiege-hackathon 做一个可本地运行的客户跟进后台。
使用者是销售主管；核心流程是录入客户、记录跟进、按状态筛选。请使用真实持久化，给出启动命令，并实际跑通核心流程。
```

### 项目图片：`$jiege-imgen`

它用于把图片需求落成项目文件。没有参考图时生成新图；提供参考图时走编辑流程并保留指定构图或主体。图片会默认写入项目合适的素材目录，并在用于当前项目时接入实际页面。它不会用图片替代按钮、表单等交互界面。

适合这样提需求：

```text
使用 $jiege-imgen 为当前 Web 项目生成首页 Banner。
主题是仓库管理，横向比例，留出左侧标题区域，风格克制、清晰。保存到 public/images/ 并接入首页。
```

## 复制给 Agent

将下面整段复制给 Agent，再替换尖括号中的内容。它会根据任务自动选用本仓库中最匹配的技能；若你已确定技能，可把“自动选择”改成 `$jiege-hackathon` 或 `$jiege-imgen`。

```text
请使用 /Users/ke/code/skills 中与本任务最匹配的技能（自动选择；如有明确技能名，以明确技能名为准）。先读取该技能目录的 SKILL.md，并严格遵守其中的适用范围、技术约束和验证要求。

任务目标：<要完成什么>
项目路径：<项目绝对路径；没有现有项目则写“新建项目”>
已有条件：<现有技术栈、参考图、接口、数据或限制；没有则写“无”>
验收结果：<用户能够完成的关键操作和可见结果>

要求：
1. 先检查项目现状和已有约定；已有项目优先沿用现有技术栈与目录结构。
2. 直接完成实现，不只给方案、静态页面、截图或伪造结果。外部发布、生产写入、发送消息等有副作用的操作先说明并等待确认。
3. 使用真实数据处理和持久化路径；外部服务暂不可用时明确标注模拟边界和切换方式。
4. 实际运行并验证核心流程，报告可复现的启动命令、验证结果、改动文件和剩余限制。
5. 不泄露或写入 API Key、Token 等敏感信息；保留工作区中与任务无关的已有改动。
```

## 安装与发现

将本仓库中的技能目录安装或复制到 Codex 的 skills 目录后，重新打开任务即可使用。每个技能的入口文件是 `SKILL.md`，并包含可供界面展示的 `agents/openai.yaml`。

```text
skills/
├── jiege-hackathon/  # 从业务想法到可验收产品
└── jiege-imgen/      # 项目图片生成与编辑
```

技能的详细约束以各目录下的 `SKILL.md` 为准。
