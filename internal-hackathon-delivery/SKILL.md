# 内部黑客松交付

## 核心目标

把真实业务问题压缩成一个可运行的最小产品。优先完成核心流程、真实数据和部署演示，不堆砌功能，不以复杂架构代替业务价值。

## 执行流程

1. 用一句话明确使用者、业务问题和预期结果。
2. 只保留一条核心业务流程，控制在 3 至 5 个操作步骤。
3. 根据项目类型选择默认技术架构，并给出最小目录结构。
4. 先完成输入、处理、保存、查询和结果反馈闭环。
5. 再补充异常提示、测试数据、部署说明和演示脚本。
6. 最后检查能否现场启动、重复演示和独立验收。

## 默认技术架构

### Web 与内部管理工具

新建项目默认使用：

- 前端：DaisyUI + Tailwind CSS，可使用简单 HTML 模板或轻量前端框架
- 后端：Node.js + Koa
- 数据库：SQLite
- 接口：简单 REST API
- 部署：单体应用优先，提供 `npm install`、启动命令和服务器部署说明

除非用户明确指定，或现有项目已有稳定技术栈，不主动更换为 React 全家桶、微服务、消息队列、复杂权限系统或多 Agent 架构。

### 爬虫与数据采集项目

默认使用 Python 完成采集、清洗和定时任务：

- 普通网页优先使用 `requests` + `BeautifulSoup`
- 必须执行 JavaScript 时再使用 Playwright
- 数据优先保存到 SQLite
- 需要管理、查询或展示数据时，补充 Koa API 和 DaisyUI Web 页面
- 必须说明采集频率、失败重试、去重方式和合规边界

### 小程序项目

小程序只作为前端，不得把全部业务写在客户端：

- 小程序端负责界面、交互和调用 API
- 服务端默认使用 Node.js + Koa
- 数据默认保存到 SQLite
- 提供接口地址、环境变量和服务器部署说明
- 条件允许时，提供复用同一后端的 DaisyUI 管理端或 Web 演示端

## 工程约束

- 优先单体应用、单数据库和少量接口，确保学员能够理解和维护。
- 使用真实可持久化的数据，不得仅用前端变量、截图或写死结果冒充完成。
- AI 能力只放在明确业务步骤，并为超时、失败和无结果提供降级处理。
- 外部接口暂不可用时，可以使用本地模拟接口，但必须保留真实调用位置和替换说明。
- 修改已有项目时优先保留可运行部分，不为统一技术栈进行无必要重写。

## 最低交付物

必须包含：

- 可运行源代码
- README 启动和部署说明
- 一条端到端业务流程
- 可持久化测试数据
- API 或主要数据流说明
- 3 分钟演示脚本
- 已知问题和后续改进清单

## 验收规则

不接受纯 PPT、纯静态页面、只有截图、只有前端壳或依赖写死数据的作品。验收时必须现场启动，完成一次真实输入、处理、保存、查询或结果反馈，并证明刷新或重启后关键数据仍然存在。

## 输出格式

协助团队时，按以下结构简洁输出：

1. 产品目标
2. 核心流程
3. 技术架构
4. 项目目录
5. 今日实现任务
6. 验收清单
7. 风险与删减建议
