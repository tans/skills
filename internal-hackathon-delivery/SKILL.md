# 内部黑客松交付

## 目标

把真实业务问题压缩成一个可运行的最小产品。优先完成核心流程、真实数据流和现场演示，不堆砌功能。

## 执行流程

1. 用一句话明确用户、问题和可验证结果。
2. 只保留一条核心业务流程，控制在 3 至 5 个操作步骤。
3. 根据项目类型选择下方默认架构；除非已有项目需要延续，否则不要随意更换技术栈。
4. 先实现输入、处理、保存、查询或结果反馈的完整闭环，再增加 AI、自动化和视觉效果。
5. 准备测试数据、异常提示、启动命令、部署说明和 3 分钟演示脚本。
6. 最后按验收规则实际运行并检查，不以截图、口头描述或计划代替交付。

## 默认技术架构

### Web 与管理后台

新建 Web 项目默认使用：

- Node.js
- Koa
- SQLite
- DaisyUI

优先采用简单单体 B/S 架构，由 Koa 同时提供 API 和静态前端服务。除非业务明确要求，不主动引入 React、微服务、消息队列、复杂权限系统或多 Agent。

### 爬虫与数据采集

爬虫、网页采集、文件处理和自动化任务默认使用 Python。必须保存采集结果并提供失败重试、日志和去重机制。需要人工查询、审核或管理时，再补充 Koa + SQLite + DaisyUI 的轻量 Web 管理端。

### 小程序

小程序只作为客户端，必须配套 Node.js + Koa 后端，业务数据保存到 SQLite 或用户指定数据库。必须说明接口地址、环境变量、服务器启动与部署方式。条件允许时，增加复用同一后端的 Web 管理端或演示端。

## 内置生图

当项目需要原创 Logo、Banner、封面、插图、背景图、空状态图或演示素材时，运行：

```bash
python3 scripts/generate_image.py \
  --prompt "清晰描述主体、用途、构图、风格和画面比例" \
  --size 1536x1024 \
  --quality high \
  --output ./public/images/banner.png
```

必须遵守：

- 固定使用模型 `gpt-image-2` 和服务地址 `https://token.minapp.xin/v1`。
- 优先调用 `/images/generations`；该路径重试后仍失败，再自动切换 `/responses` 的 `image_generation` 工具。
- 两条路径默认各执行 1 次请求并最多重试 2 次，使用指数退避；不得因单次超时立即放弃。
- 可用 `--retries` 调整每条路径的重试次数，但不要无限重试；默认两条路径合计最多请求 6 次。
- 从 `~/.codex/auth.json` 的 `OPENAI_API_KEY` 读取密钥。
- 不把密钥复制进代码、README、日志、前端文件或最终交付物。
- 生图结果必须保存到项目目录并由实际页面引用，不能只生成后不使用。
- 产品界面优先使用 DaisyUI 组件；不要用图片替代可交互界面。
- 两条接口均失败时，报告最后错误和已尝试的接口，不私自切换模型、地址或其他生图服务。

如需从文件读取长提示词：

```bash
python3 scripts/generate_image.py \
  --prompt-file ./image-prompt.txt \
  --output ./public/images/cover.png
```

## 技术原则

- 单体应用优先，依赖少、一条命令可启动。
- 使用真实可持久化数据，禁止只保存在前端变量中。
- AI 只用于明确步骤，并提供失败、超时和无结果时的降级方案。
- 外部业务接口暂不可用时，可以使用本地模拟接口，但必须保留真实数据流和替换说明。
- 已有项目优先在原技术栈上补全交付，不为了统一架构无意义重写。

## 最低交付物

必须包含：

- 可运行源代码
- README 启动与部署说明
- 一条端到端可操作流程
- 可持久化的测试数据
- 3 分钟演示脚本
- 已知问题与后续改进清单

## 验收规则

不接受纯 PPT、纯静态页面、只能展示截图或大量写死数据的作品。验收时必须现场启动，完成一次输入、处理、保存、查询或结果反馈，并证明刷新或重启后关键数据仍然存在。小程序必须同时验证 Koa 后端可用；爬虫必须展示一次真实采集或可复现的测试任务。

## 输出格式

协助团队时，简洁输出：

1. 产品目标
2. 核心流程
3. 推荐架构
4. 今日实现任务
5. 生图素材需求（没有则省略）
6. 验收清单
7. 风险与删减建议
